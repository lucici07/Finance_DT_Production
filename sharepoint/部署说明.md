# WeeklyCatch-Up 安装步骤

目标站点：https://lenovonam.sharepoint.com/sites/WeeklyCatch-Up

当前安装包已生成，本地干净构建和 11 项相关测试通过。尚未安装到公司 SharePoint，也未验证真实账号保存。

重新打包可在项目根目录运行 node sharepoint/build.mjs；本机可加 --temporary 复用构建缓存。无需修改 Windows 脚本执行策略。

## 交给 SharePoint 管理员

这是一个 SPFx Web Part，用公司登录身份读写本站点的 SharePoint Lists，不需要另开数据库或配置应用密钥。

请把构建后的 finance-weekly-sharepoint.sppkg 上传并部署到公司或站点 App Catalog，再把 FinanceWeekly 添加到 WeeklyCatch-Up 的现代页面。若没有 App Catalog，需要 SharePoint 管理员协助。单纯上传到 Shared Documents 不会安装应用。

安装包路径：
finance-weekly-sharepoint/sharepoint/solution/finance-weekly-sharepoint.sppkg

## 第一次使用

1. 编辑 Web Part 设置，确认站点地址和财年起始月份。暂定 4 月，可改；FY2026 表示从 2026 年开始的财年。
2. 站点管理员打开页面，点击 Set up FY ... list，创建列表和索引。
3. 给组员开通页面及列表的读、添加和编辑权限。创建列表需要额外的列表管理权限，普通组员不需要负责创建。
4. 每个人默认看到自己的工作区。切到 Editing 编辑，点击 Save 保存。
5. 老板从 Workspace 选择人员，或打开对方复制的 Share 链接，只读查看其工作区。人员第一次保存后会出现在列表中。
6. 新财年点击 Open year，再由站点管理员初始化新年度列表；旧年度仍可以打开。

## 存储方式

每财年一个 List。每人一条工作区索引记录；每次保存新增一个快照记录，完整内容放在 workspace.json 附件中，然后更新工作区指针。

这种方式可以保留周报、自定义列、日历待办及其关联，不需要把现有功能全部重写。周报内容仍在网页内编辑，不能直接在 Lists 表格里逐条编辑。约 20 条个人索引记录之外，还会增加保存历史；按人员的索引查询和按 ID 读取快照，不会扫描全部历史。

保留的快照会占用 SharePoint 站点空间。请与站点管理员约定历史保留策略；不能删除正在被 SnapshotId 引用的快照。失败或冲突的保存也可能留下未引用快照。

一个人在一个财年使用一个工作区。当前网页中多个独立分享链接的“工作区收藏”不会自动合并或迁移；请先选择需要迁移的数据备份。

## 迁移及验证

从原应用导出完整 JSON 备份。在 SharePoint 应用选择目标财年、切换到 Editing，使用 Import workspace backup 导入，检查后再点击 Save。Excel 只包含部分表格，不能代替完整备份。没有自动读取或修改现有线上数据。

请先用两个真实公司账号验证：本人保存与重开、老板查看、历史财年、日历联动、自定义列、导出、两个窗口冲突。成员之间没有严格的数据隔离；拥有列表编辑权限的人可以通过 SharePoint 直接操作记录。

本地测试不等于公司站点联调通过。部署和真实登录验证必须在公司环境完成。

如果原站点没有完整 JSON 下载按钮，可在项目终端使用只读导出工具：
node sharepoint/export-existing.mjs "完整工作区链接（含 #share=...）" runtime/workspace-backup.json
必须先创建 runtime 文件夹。工具不会覆盖同名文件；备份含个人工作内容，应保存在 runtime 等不提交到 Git 的位置。不要把只有首页的 URL 或 workspace-links.json 当作工作区内容备份。
